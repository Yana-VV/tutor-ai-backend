# Tutor AI Backend API

REST API сервис для проверки дневных и еженедельных записей наблюдений.

## 1. Как запустить проект и тесты

### Запуск проекта

Необходим Docker и Docker Compose.

Клонировать репозиторий:

```bash
git clone <repository-url>
cd <project-directory>
```

Создать `.env` из шаблона:

```bash
cp .env.example .env
```

Запустить приложение:

```bash
docker compose up --build
```

При запуске PostgreSQL поднимается отдельным контейнером, после проверки готовности базы автоматически выполняются миграции Alembic и запускается FastAPI.
API:

```text
http://localhost:8000
```

Swagger:

```text
http://localhost:8000/docs
```

### Запуск тестов

Запуск тестов внутри работающего контейнера:
```bash
docker compose exec web pytest -v
```

Тесты покрывают определение типа документов, проверку комплектности, неизвестные файлы, недопустимые расширения и превышение размера файла.

## 2. Технологии и почему они использованы

* **Python 3.11** — основной язык проекта.
* **FastAPI** — REST API, удобная работа с файлами, валидация входных данных и автоматическая Swagger/OpenAPI документация.
* **PostgreSQL** — хранение результатов проверок, документов и найденных ошибок.
* **SQLAlchemy** — ORM для работы с PostgreSQL; используется синхронное подключение, так как текущая бизнес-логика не требует асинхронной работы с БД.
* **Pydantic** — описание и валидация схем API.
* **Alembic** — управление миграциями базы данных.
* **Pytest** — автоматическое тестирование бизнес-логики.
* **Docker / Docker Compose** — воспроизводимый запуск приложения и PostgreSQL в контейнерах.

## 3. Архитектура решения

Проект разделён на API-слой, бизнес-логику и слой работы с данными.

```text
Client
  │
  ▼
FastAPI (main.py)
  │
  ▼
Бизнес-логика (services.py)
  │
  ├── определение типа документа
  ├── проверка формата и размера
  ├── проверка комплектности
  └── формирование итогового статуса
  │
  ▼
SQLAlchemy (models.py / database.py)
  │
  ▼
PostgreSQL
```

### `main.py`

Отвечает за HTTP API:

* `POST /api/checks`
* `GET /api/checks`
* `GET /api/checks/{check_id}`

Также принимает файлы и дополнительные поля запроса и сохраняет результат проверки в БД.

### `services.py`

Содержит основную бизнес-логику проверки:

* определение типа материала по имени файла;
* проверка расширения;
* проверка размера;
* проверка обязательных материалов;
* формирование `error` и `warning`;
* формирование итогового статуса.

### `models.py` / `database.py`

Отвечают за хранение данных и работу с PostgreSQL.

Основные сущности:

* `Check` — информация о проверке;
* `Document` — информация о файлах;
* `Issue` — ошибки и предупреждения.

## 4. Ограничения текущей версии (AI-модуль)

На данном этапе сервис отвечает исключительно за маршрутизацию, валидацию файлов и формирование статуса комплектности. 

Автоматическое извлечение данных из текста документов пока не реализовано, так как эта задача находится в зоне ответственности будущего AI-модуля. В текущей версии эти поля заполняются вручную или содержат тестовые данные, чтобы заранее подготовить структуру ответа под будущее подключение нейросети.

## 5. Переменные окружения

Настройки приложения передаются через `.env`.

| Переменная          | Назначение                    |
| ------------------- | ----------------------------- |
| `POSTGRES_USER`     | Пользователь PostgreSQL       |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL             |
| `POSTGRES_DB`       | Название базы данных          |
| `POSTGRES_HOST`     | Хост PostgreSQL               |
| `POSTGRES_PORT`     | Порт PostgreSQL               |
| `DATABASE_URL`      | Строка подключения SQLAlchemy |

Пример:

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=tutor_ai
POSTGRES_HOST=localhost
POSTGRES_PORT=5433
DATABASE_URL=postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@${POSTGRES_HOST}:${POSTGRES_PORT}/${POSTGRES_DB}
```

Приложение загружает конфигурацию из `.env` через Pydantic Settings.

При запуске через Docker Compose приложение подключается к PostgreSQL по адресу db:5432. Значения POSTGRES_HOST и POSTGRES_PORT из .env для контейнера приложения переопределяются в docker-compose.yml.
